# 08 设计手册：顺着骨架搭插件

适用 **0.2.1-rc.2**。本篇不是 API 清单，而是**判断标准**——决定"这么设计对不对"。

## 一、先定"你是谁"

在写第一行代码前回答三个问题：

1. **我提供能力，还是消费能力？** 提供 → 服务类默认导出 + `inject` 声明依赖；消费 → 函数插件。
2. **我改的是行为，还是策略？** 行为 → 新插件行；策略 → 事件监听或 `guard` / `restrict`。
3. **我的东西要不要在别的 agent 里长得不一样？** 要 → 作用域注册；不要 → 全局注册。

答不清这三题，写出来的插件通常是"能跑但接不进生态"的那种。

## 二、所有权：每个注册都要能还回去

- 一律用 `ctx.effect()`、`ctx.on()`、注册表自带的回收语义，**不要手写 add/remove 配对**。
- 注册到**别的 context**（如 `agent.ctx`）的东西有**两个拥有者**：对方 context 也会回收，你自己也要留一份 disposer，否则重复卸载或幽灵注册。
- 有顺序依赖的清理放进**同一个** `ctx.effect()` 的返回函数里串行 await；分散在多个 effect 里就只能得到"逆序开始、并发执行、不保证完成"。

**自检**：卸载插件后再挂回来，贡献数量应该回到原值，而不是翻倍。

## 三、依赖：`inject` 是硬承诺，`ctx.get` 是软探测

| 你想要的语义 | 写法 | 后果 |
|---|---|---|
| 没有它我就不能工作 | `inject = ['tools']` | 对方缺失时**我不启动**（正确） |
| 有就用，没有就降级 | `ctx.get('x')`（不写 inject） | 随时可能 `undefined`，要判空 |
| 必须在它就绪后才能注册 | `inject` + 在 `apply` 里注册 | 依赖消失会自动 dispose 我的贡献 |

常见错误：为了"稳妥"把所有服务都塞进 `inject`，结果用户少装一个可选插件，你的插件整个不启动。

## 四、隔离：别污染别人的树

- 需要"只在某个子树生效"的替换，用 `ctx.isolate(...)`，不要改全局服务。
- 需要按 agent 不同的可见性，用作用域注册（`dsh-scope` 的链式层），不要用模块级变量当开关。
- 给别的 agent 注册时记住：作用域消失，注册也该消失。

## 五、配置：跨部署会变的值必须是字段

判断标准：**能不能只改 `cordis.patch.yml` 就换掉这个值**。能，就不是配置字段。

- 用 Schemastery schema，不导出普通对象；字段默认值写成 `.default(...)`。
- 需要"改了立刻生效、不重跑 apply"的用 `.volatile()`，读值用引用 `config.x.get()`。
- 命名空间与 profile 里的行 `id` 绑定；**改 `id` 会静默孤儿化设置卡片**。

## 六、失败姿态要先选，不要事后补

| 姿态 | 适用 | 代价 |
|---|---|---|
| fail-closed（拒绝并诊断） | 安全、权限、数据完整性 | 误杀会让用户干不了活 |
| fail-open（降级继续） | 展示、遥测、非关键增强 | 问题被静默 |

选完要保证：**诊断里说清"为什么被拒"，以及"怎么恢复"**。DSH 官方的兼容门就是范本：拒绝时给出 `allow-version ... --accept-risk` 的完整命令。

## 七、token 成本是设计约束，不是优化项

- 工具描述、提示词段、技能目录**每轮都可能付费**。加东西前先问能不能变成配置默认值或 `guard`。
- 技能目录只渲染 `name` + 归一化后截断的 `description`（500 字符），所以**重要信息写前面**。
- 大输出要用分页/有界机制，不要"先返回再说"。

## 八、升级兼容：写给一年后的自己

- 声明 `engines.dsh`（一旦声明，它单独决定兼容性，peer 被忽略）。
- 不覆盖别人的 `id` 就尽量别依赖别人的内部行为；需要依赖时写进 README 的"兼容性"段。
- 监听事件时不要假设顺序，除非用 `prepend` 且真的需要。
- 用别人的服务时，只依赖 `ctx.<key>` 的公开方法，不 import 实现包。

## 九、自检清单（提交前）

- [ ] 卸载后贡献归零，重挂后不翻倍
- [ ] 缺可选依赖时能降级而不是不启动
- [ ] 所有注册都有 disposer，跨 context 的留了两份
- [ ] 配置字段可通过 `cordis.patch.yml` 改；volatile 字段用引用读
- [ ] 失败有可操作诊断
- [ ] 工具/提示词对 token 的影响能说清楚
- [ ] `engines.dsh` 与 peer 依赖写对（见 `../plugin-package.md`）

## 十、反模式速查

| 症状 | 多半是 |
|---|---|
| 插件在别人的会话里消失 | 用了全局状态或模块级单例 |
| 热重载后重复两次 | 注册没走 effect，或跨 context 没留 disposer |
| 官方行为莫名不见了 | waterfall 忘了 `next()` |
| 用户少装一个插件我这就起不来 | 可选依赖错写成 `inject` |
| 设置卡片找不到 | 行 `id` 变了，或 schema 没导出 |
| 升级后我静默失效 | 依赖了别人的内部行为，或 `config` 被整体替换 |
